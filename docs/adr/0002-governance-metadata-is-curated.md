# ADR 0002: Governance metadata is curated, never derived

Date: 2026-09-06
Status: accepted

## Context

Risk levels and permission footprints were first generated by keyword regexes over SKILL.md text. Eight of thirty-nine skills carried wrong classifications within hours: `eng-router` (a read-only index) scored critical because its routing table mentions firewall and ship; `eng-execute` (writes code) scored low. Derived governance data drifts silently because regeneration overwrites any correction.

## Decision

Risk, permissions, owner, status, maturity, and review cadence for every skill live in the hand-curated `CURATED` table in `scripts/generate-manifests.mjs`. Nothing derives them from prose. A packaged skill without a curated entry fails generation and the test suite.

## Consequences

New skills cost one deliberate curation decision; uncurated additions are impossible to ship by accident. The escalation policy (code writers never below high; remote/host operations critical; read-only low) is enforced by `tests/governance.test.mjs`, so weak curation also fails loudly. Cost: the table must be touched for every addition, which is the point.

## Alternatives considered

- Per-skill hand-edited manifest.yaml files: rejected, hand edits drift from SKILL.md and break the single-source rule the manifests exist to enforce.
- Heuristic derivation with manual overrides: rejected, the heuristic still produces silent wrong answers for every skill nobody remembered to override.
