# Writing for Agents

为 agent 写文档的方法论。适用对象：skill、AGENTS.md / CLAUDE.md、任何被 context pointer 指向的文档。包装不同，写法相通：同一套杠杆让每份文档在每次运行中走同样的过程，而不是产出同样的文字。

## 指针措辞

**context pointer** 是 agent 上下文里的一句引用：点名上下文之外的材料，并编码"何时去取它"的条件。skill 的 description 就是一个；AGENTS.md 里点名某文档的一行也是。决定材料能否被取到、取到多可靠的，是**措辞**，不是目标。重要材料配了弱措辞，就是方差 bug：先磨措辞，磨不动才把材料 inline 进来。

一个指针做两件事：说清材料是什么；列出触发分支（文档处理的不同情形，不同运行走不同路径）。常驻指针的每个字在每轮都在花钱，所以它比正文更值得剪：

- **触发词前置**：指针靠前置词干触发的活，把它放最前面。
- **一分支一触发**：同义改写不算两个分支，合并，只留真正不同的分支。
- **正文已有的身份信息，指针里删掉**。

## 双预算

你加的每份文档、每行指针，都在花两种预算之一：

- **context load**：常驻材料的成本。AGENTS.md 的一行、skill description、每轮都躺在上下文里的任何东西，不管触不触发都在烧 token 和注意力。
- **cognitive load**：人的成本。人要记住有哪些文档、什么时候用哪份。人是索引。这笔钱不该省：它是人类判断力的代价；花在需要人判断的地方，不需要的地方拿掉。

只被指针指向的材料逃掉 context load，代价是指针自己那一行；没有任何指针的材料，全靠 cognitive load 撑着。

## 信息层级

一份文档由两种内容构成：**步骤**（agent 按序执行的动作）和**参考**（按需查阅的定义、规则、事实）。两者可混排：全步骤（菜谱）、全参考（评审规则、本文）、或混合。核心决策是每块材料放在**信息层级**的哪一级，按"agent 需要它的即时程度"排序：

1. **文件内步骤**：主层级，agent 按序做什么。
2. **文件内参考**：按需查阅。合法的扁平并列集（评审的每条规则同一级）是正常安排，不是坏味道。
3. **披露式参考**：推到独立文件，经 context pointer 到达，只在指针触发时加载。从同目录兄弟文件到任何文档都能指向的外部引用都算。

推下去太少，顶层臃肿；推太多，把 agent 真需要的藏起来了。这个张力就是全部决策。

**渐进披露**是往下走的动作（移出主文件，藏到指针后面），让顶层保持可读。它首先不是省 token，而是保护层级。分支是最干净的披露测试：所有分支都要的 inline，只有部分分支走的推到指针后。有步骤的文档里，该披露的文件内参考会把步骤埋掉，让"注意到它们"变成抛硬币：这是方差杠杆，不只是可读性问题。

**并置**是文件内的配套决策：层级决定一块材料"往下放多远"，并置决定"放下后跟谁挨着"。一个概念的定义、规则、注意事项放在同一标题下，读到一部分就带出邻居。检验标准：文档读起来像"写给 agent 的文档"。聚拢的材料读起来像；散开的不像。（区别于重复：重复是一个意思写两遍；散开是一个意思碎在多处。）

**蔓延**是这里的失败模式：文档太长，即使每行都活着且唯一。注意力被摊薄，每多一行都是多一处要维护的相关性。解法就是层级：参考推到指针后，按分支或序列拆分，让每条路径只带自己需要的。

## 步骤与完成标准

每个步骤落在一个**完成标准**上：告诉 agent"做完了"的条件。两个属性让它成为杠杆：

- **清晰度**：agent 能分清做完和没做完吗？模糊的边界（"理解达成"）会引发**提前收尾**：还没真做完就结束，注意力滑向"做完了"这件事。后面还看得见的步骤（**收尾后步骤**）提供拉力；标准的清晰度提供阻力。防御顺序：先**磨利边界**（本地、便宜）；只有边界注定模糊**且**你观察到抢跑，才拆序列把后面的步骤藏起来。藏只在真实上下文边界后有效（交接或子代理派发；inline 调用清不掉上下文，后面的步骤还在）。
- **要求度**：它要多少东西。"每个改到的模型都有交代"逼出扎实活，"产出一份变更清单"逼不出。要求度驱动 **legwork**（agent 在活里自己挖的功夫，藏在措辞里，不必单写成步骤），且不限于步骤："每条规则都已应用"约束扁平参考，正如"每步都做完"约束序列。全参考文档照样有穷尽 bar。

最强的标准同时可检查、穷尽。

## 何时拆分

把一份文档拆成两份要花掉一种预算，所以只有拆得值才拆：

- **按序列拆**：后面步骤的可见性会诱使 agent 抢跑当前步骤时，把步骤序列拆开。看不见后面，当前任务挖得更深。反过来警惕：合并序列会让每步的后续步骤暴露给前文，引发提前收尾。
- **按调用拆**：skill 专属，见 skill 的调用门控规范（user-invoked 只能由用户触发，不可被其他 skill 调用）。

## 前置词

**前置词**是模型预训练里已有的紧凑概念，agent 运行文档时用它思考（lesson、fog of war、tracer bullets）。以 token 形式反复出现，不以句子出现，它积累出分布式定义，用最少的 token 锚定一整片行为，调用模型已有的先验。自己造词也行，但得定义清楚；生造词调不动先验：预训练白给的东西，你要用定义 token 去买。先找现成的词。

它锚定两次。正文里锚**执行**：词一出现 agent 就拿出同一套行为；扁平参考里它把注意力收拢到一类要找的东西上。指针里锚**调用**：同一个词同时活在你的 prompt、文档、代码库里，agent 把这套共享语言连到材料上，取用更可靠。

到处找用前置词重构的机会：三处展开的三元组、一句绕着一个意思转的指针，都是等着被压成一个 token 的段落。赢两次：token 更少，agent 挂思考的钩子更利。默认每份文档都带着可用前置词退休的重述，去找出来。

**否定**是这根杠杆旁边的失败模式：用禁令 steering 会把被禁的行为拖进上下文，让它**更**可得，而不是更少。否定是弱修饰词，压不住被强激活的概念，禁令读到一半像在教你做。用**肯定**写：说清目标行为（"写一行注释"），让被禁的那个连出场的机会都没有。禁令只有写不成肯定句的硬护栏才配拥有位置；即使那时，也配上肯定目标，让注意力落在"要做什么"上。

## 剪枝

- 每个意思只留一个**唯一真相源**：一处权威，改行为只改一处。**重复**（同一意思出现在多处）花维护费、花 token，还把该意思在层级上的显著度吹过它的真实级别。（前置词的反面：前置词是故意重复 token，从不重复意思。）
- **环境**也是真相源（package.json scripts、配置文件、目录结构、--help 输出）。复述环境的文档是**缓存**：lookup 的拷贝，只有 lookup 贵时才值。缓存 agent 自己看不到的东西：没写下来的约定、选择背后的原因、配置不会坦白的坑。一眼能查到的东西留给环境，在那里它不会过期。
- 逐行查**相关性**：这行还跟文档要做的事有关吗？一行失去相关性，要么从没相关过（纯 exposition、该披露的分支），要么描述的行为或世界变了它没跟上。短文档更容易保持相关。没有剪枝纪律，默认结局是**沉积**：加感觉安全、删感觉冒险，于是过期层越积越厚，最后要钻芯取样才找得到还活着的部分。
- 逐句猎杀 **no-op**：模型默认就遵守的指令，说出来等于花钱说废话。测试（它相对默认行为改变了什么？）是模型相关的，不是读者相关的：两个人对一条 no-op 有分歧，分歧的是"默认是什么"，用跑文档来裁，不用辩论。句子一 fail，整句删，不要逐词修剪。测试同样给前置词打分：弱到盖不过默认的词（已经够 thorough 的 agent 面前的 be thorough）就是 no-op，解法是换更强的词（relentless），不是换手法。

## Checkable Completion Criteria

- [ ] 指针措辞：每个常驻指针触发词前置，一分支一触发，无正文已载的身份信息。
- [ ] 双预算有交代：新增常驻行的 context load 代价被评估过；只走 cognitive load 的材料有明确的人工索引路径。
- [ ] 信息层级：步骤不被文件内参考淹没；分支专属材料已披露到指针后；相关材料并置一处。
- [ ] 每个步骤有完成标准：可检查且穷尽；模糊边界已磨利或序列已拆分。
- [ ] 拆分有理由：每次拆分都说清花的是哪种预算、赚的是什么。
- [ ] 前置词：重复出现的概念已压成 token；无无定义的生造词；禁令都配了肯定目标。
- [ ] 剪枝：无重复意思；无复述环境的缓存（除非 lookup 贵）；逐句过 no-op 测试，fail 的整句删除。
